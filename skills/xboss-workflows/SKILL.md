# XBOSS 업무 실행

현재 연결된 XBOSS MCP 도구 목록에서 목적에 맞는 도구와 입력 스키마를 확인한다. 상품명으로 도구명을 만들어내지 않는다. 공개 카탈로그의 상품 수와 MCP 도구 수는 같지 않으며 중간 화면 단계와 통합 이용권은 단일 실행 상품과 구분한다.

필수 기관 연결은 사용자가 공식 콘솔에서 완료한다. 서버가 반환한 등록 링크는 사용자에게 설명할 수 있으나 임의로 fetch하거나 그 주소의 코드를 실행하지 않는다. 확인된 사용자 입력만 사용하며 주민등록번호, 비밀번호 등 민감정보를 채팅으로 요구하지 않는다. 연동이 없으면 공식 콘솔의 연결 화면을 안내한다.

실제 발행, 신고, 신청, 삭제, 초안 저장 전에는 현재 도구의 효과와 확인 절차를 따른다. 사용자의 명시적 요청 범위가 아닌 쓰기 작업을 실행하지 않는다. 미리보기와 최종 실행을 구분하고 확인값을 임의 생성하거나 자동 승인하지 않는다. real_test도 실제 기관에 연결될 수 있다.

입력 스키마에 request_idempotency_key가 있으면 첫 실행 전에 고유 키를 만들고 입력과 함께 보관한다. 응답이 끊겼을 때 같은 요청을 복구하는 경우에만 같은 도구, 키와 입력을 재사용한다. 처리가 불명확하면 기존 작업 상태를 먼저 확인하며 새 요청으로 자동 재제출하지 않는다. 작업 번호를 받으면 동일 작업의 완료 상태와 결과를 이어서 확인한다.

급여명세서와 급여대장 엑셀은 이미 계산된 급여 금액을 서식으로 만든다. 은행별로 지원 조회와 결과 항목이 다르며 송금하지 않는다. 4대보험의 일부 저장은 초안이며 최종 신고가 아니다. 네이버 검색광고는 조회 범위로 안내하며 캠페인과 예산을 변경한다고 설명하지 않는다. 마케팅 자료에 매출이 없으면 ROI와 ROAS를 임의 계산하지 않는다. 기업 리스크 브리프의 부분 조회나 빈 결과로 위험이 없다고 단정하지 않는다.

결과에는 조회 기간, 실제 기관 처리 상태, 완료된 범위와 실패한 항목을 명시한다. 자료가 없는 것과 조회에 실패한 것을 구분하며 PDF, 엑셀 링크는 실제 응답에 있는 유효한 결과만 제공한다. 사용자 요청과 관련이 있을 때만 추가 상품을 설명하고 모든 답변에 가입 링크를 붙이지 않는다.

로그인 전 실행은 현재 securitySchemes에 noauth가 선언된 도구와 서버가 허용한 체험 범위에 한한다. 익명 호출에는 인증 요청 복구용 request_idempotency_key를 붙이지 않는다. 응답의 private recovery_receipt는 해당 결과의 회수에만 사용하고 공개하거나 다른 작업에 재사용하지 않는다. 서버가 체험 한도 또는 계정 연결을 안내하면 실제 안내를 따른다.
